   - Import IORedis, create connection with REDIS_URL env var

   - Queue name: 'messages'

3. **src/api/routes/webhook.ts** — POST /webhook/whatsapp:
   - Receive Evolution API webhook payload
   - Only process events where `event === 'messages.upsert'` (Evolution API v2 uses dot notation)
   - Also handle 'MESSAGES_UPSERT' for compatibility
   - Extract: instance name, phoneNumber (remoteJid stripped of @s.whatsapp.net), message text content, messageId
   - Skip messages from self (key.fromMe === true)
   - Enqueue via messageQueue.add() with deduplication: { id: `${instance}-${phoneNumber}`, ttl: 1000, extend: true, replace: true } and delay: 1000 (1s debounce window to merge rapid messages)
   - Return { status: 'queued' } immediately — MUST return in <500ms
   - Register as Fastify plugin

4. **src/queue/workers/message.worker.ts** — BullMQ Worker:
   - IORedis connection with { maxRetriesPerRequest: null } (CRITICAL — prevents crash on Redis hiccup)
   - Worker on queue 'messages', concurrency: 5
   - Job processor: extract instance + phoneNumber + message from job.data
   - Phase 1 behavior: Echo reply — send back "[Echo] {original message}" via evolutionClient.sendText
   - Log job processing with pino-style console.log (job id, phone, message preview)
   - Handle 'failed' event with error logging
   - Export messageWorker

5. **Update src/main.ts** — Import and start messageWorker after server listen. Graceful shutdown: close worker, close server on SIGTERM/SIGINT.
